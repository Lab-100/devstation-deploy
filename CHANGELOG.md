# Журнал изменений (CHANGELOG)

Все значимые изменения этого репозитория. Формат по [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/),
версия — по схеме «основная.младшая».

## Соглашения о версиях

- Схема: **две части, `X.Y`** (без третьего компонента), в сообщениях и тегах — с префиксом `v`:
  `v0.3.2`. Значение хранится в `$Script:DeployVersion` в [`deploy.ps1`](deploy.ps1) и разъезжается
  при релизе: тег `vX.Y` + запись в `$Script:DeployVersion` + запись в этот файл.
- Релизы публикуются **только по явной команде владельца «в релиз»** (см. `config/AGENTS.md.template`,
  раздел «Проекты: приватные репозитории GitHub»). Поэтому изменения ниже раздела «Не выпущено»
  могут лежать в `main` без тега и без изменения `$Script:DeployVersion`.
- Повышение младшей части — для небольших изменений; повышение основной части — для несовместимых
  или крупных изменений. При схеме `0.X.Y` третья часть не используется, совместимость внутри
  ветки `0.X` подразумевается.

## Не выпущено

### Качество кода — непрерывная проверка PowerShell (CI)

Добавлен GitHub Actions workflow [`.github/workflows/powershell-quality.yml`](.github/workflows/powershell-quality.yml),
срабатывающий на `push` в `main`, на `pull request` в `main` и вручную (`workflow_dispatch`).

Что проверяется:

1. **Разбираемость всех `.ps1`/`.psm1` парсером PowerShell — блокирующая проверка.** Синтаксическая
   ошибка в скрипте развёртывания ломает деплой на целевой машине, поэтому это единственная проверка,
   которая обязана валить сборку. При ошибке выводится файл, строка, позиция и текст сообщения.
2. **PSScriptAnalyzer — отчёт + шлюз качества.** Валит сборку **только уровень `Error`** (настоящие
   дефекты). Предупреждения публикуются полностью: в лог запуска и отдельным артефактом
   `psscriptanalyzer-report` (сводка по правилам + построчный список с файлами и строками).
3. **Pester** — запускается автоматически, как только в репозитории появятся файлы
   `*.Tests.ps1` / `*.Test.ps1` (Pester 5+). Проверен локально и на Pester 6: конфигурация совместима,
   упавший тест валит сборку. Пока тестов в репозитории нет, шаг честно пропускается с сообщением —
   выдумывать тесты ради зелёного CI не выполнялось.

Осознанные решения по строгости (обоснованы замером по текущему коду, PSScriptAnalyzer 1.25.0):
всего **64** замечания, из них **0** уровня `Error`, все — уровня `Warning`. Из них 52 (81%) — два
правила, прямо противоречащих договорённостям репозитория, поэтому они исключены явным списком:

- `PSAvoidUsingWriteHost` (37) — README декларирует, что «логи команд пишутся прямо в консоль»,
  то есть `Write-Host` здесь намеренный и штатный;
- `PSUseBOMForUnicodeEncodedFile` (15) — все файлы намеренно хранятся в UTF-8 **без** BOM
  (современный стандарт; проект требует PowerShell 7). Требование добавить BOM — устаревшая
  рекомендация под Windows PowerShell 5.1.

Оставшиеся 12 замечаний (`PSAvoidUsingEmptyCatchBlock` — 6, `PSUseApprovedVerbs` — 2,
`PSUseShouldProcessForStateChangingFunctions` — 2, `PSAvoidUsingInvokeExpression` — 1,
`PSUseSingularNouns` — 1) относятся к защитным `catch`-блокам и к существующему API хелперов
(`Refresh-Path`, `Load-State`, `Set-StageDone`, `Set-UserEnv`, `Deploy-Tools`). Их «обнуление»
потребовало бы массовой правки рабочего кода девяти модулей и сломало бы совместимость
скриптов развёртывания, поэтому они задокументированы в отчёте, но не блокируют сборку.
Поднять строгость предлагается осознанно и по пунктам, отдельным изменением.

Прочее:

- `.gitignore`: добавлен `ci-report/` — каталог генерируемых отчётов не должен попадать в коммит.
- Actions закреплены на актуальных major-версиях: `actions/checkout@v7`, `actions/upload-artifact@v7`
  (проверено через `gh api`: последние релизы — `v7.0.1`).
- Workflow работает с минимальными правами (`contents: read`), секретов не требует.

Не выпущено: тег `v0.3.3` не создан, `$Script:DeployVersion` в `deploy.ps1` не поднят — по
политике репозитория релиз делается только по явной команде владельца.
